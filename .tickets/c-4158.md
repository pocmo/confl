# DISCOVERY: Audit Confluence storage format feature support gaps

Analyze what Confluence storage format features we currently support vs. what exists, and identify gaps.

## Questions to Answer
1. **What storage format features exist?**
   - Document all Confluence storage format elements (tags, macros, structures)
   - Basic elements: headings, paragraphs, lists, tables, links, images
   - Advanced elements: macros (info, warning, code, toc, children, etc.)
   - Formatting: bold, italic, underline, strikethrough, colors
   - Special elements: mentions, emojis, dates, status badges
   - Nested structures: tables in lists, macros in tables, etc.

2. **What do we currently support?**
   - Review existing rendering implementation (if any)
   - Review markdown conversion implementation (if any)
   - What works today vs. what's not implemented?

3. **What are the priority gaps?**
   - Which features are most commonly used in real pages?
   - Which features are critical for readability?
   - Which features can be safely ignored or simplified?

4. **How complex is each gap to implement?**
   - Simple (e.g., basic formatting tags)?
   - Moderate (e.g., tables, nested lists)?
   - Complex (e.g., macros with dynamic content, embedded pages)?
   - Requires discovery (e.g., handling attachments, page hierarchy)?

## Output
- Document findings in docs/architecture/storage-format-feature-gaps.md
- Create feature matrix showing:
  - Feature name
  - Current support status (✅ supported, ⚠️ partial, ❌ missing, 🔍 unknown)
  - Priority (high/medium/low)
  - Complexity estimate
- File follow-up tickets:
  - Implementation tickets for clear, straightforward features
  - Discovery tickets for features requiring research or architectural decisions
  - Group related features into single tickets where appropriate
