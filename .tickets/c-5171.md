## Investigation Results

### Space Key vs Space ID in Confluence API v2

**Space Key:**
- Human-readable unique identifier (e.g., 'DEV', 'TEAM')
- For personal spaces: tilde (~) + account ID (e.g., '~61df405068926d0068c87f43')
- Used in URLs and some API endpoints
- Can be changed by admins (though personal space keys cannot be changed)

**Space ID:**
- Immutable numeric identifier (e.g., 3277554038)
- Never changes even if space key is renamed
- Required by most API v2 endpoints

### API v2 Endpoint Behavior

1. **GET /spaces?keys={key}** - Accepts space keys (including personal space keys)
2. **GET /spaces/{id}** - ONLY accepts numeric space IDs (not space keys)

### Bug Found in Current Implementation

**Method:** `ConfluenceClient.get_space(space_ref)`
**Location:** src/confl/client.py:575-593
**Issue:** Uses `/spaces/{space_ref}` which fails for space keys

**Test Results:**
- `get_space_by_key('~61df405068926d0068c87f43')` ✓ Works
- `get_space('~61df405068926d0068c87f43')` ✗ Fails with 400 error: 'Expected type is long'

### Correct Approach

The `get_space()` method should:
1. Try to parse space_ref as numeric ID
2. If numeric: use /spaces/{id} directly
3. If not numeric (space key): use /spaces?keys={key} to look up the ID first

OR simply always use get_space_by_key() logic for both keys and IDs since /spaces?keys= accepts both.

### Impact

**Commands affected:** `confl space get <ref>`, `confl space update <ref>`, `confl space delete <ref>`
**User experience:** Users cannot use space keys (especially personal space keys like ~61df405068926d0068c87f43) with these commands - they must find the numeric ID manually.
