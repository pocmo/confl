# Handle unknown Confluence macros gracefully

Ensure converter doesn't crash on unknown macros and shows reasonable output.

From content-rendering.md:
- Many Confluence macros exist that we don't explicitly handle
- Examples: children, jira, excerpt, anchor, page-tree, etc.
- Current behavior: extracts text or returns empty string
- Need to ensure this is robust

Implementation:
1. Review convert_ac_structured_macro() fallback behavior
2. For unknown macros: extract any readable text content
3. Log warning for unknown macro types (optional)
4. Add comprehensive tests for various unknown macros

Common macros to handle gracefully:
- children (list child pages) → show placeholder
- jira (embedded issues) → extract text
- excerpt (reusable content) → show content
- anchor (internal links) → preserve as text
- page-tree (hierarchy) → show placeholder

Testing:
- Add test cases for each common unknown macro
- Verify no crashes
- Verify reasonable text output

Acceptance:
- Converter handles unknown macros without crashing
- Extracts readable text when available
- Shows placeholder or skips when no text available
- Tests cover common macro types
