# BUG: confl space list only shows subset of spaces with no indication

The 'confl space list' command only shows a limited number of spaces without indicating there are more.

## Bug Description
Running `confl space list` returns only a small subset of available spaces. Users have no way to know:
- How many spaces exist total
- That they're only seeing a partial list
- How to get the rest of the spaces

This is confusing and gives an incomplete view of available spaces.

## Root Cause
Likely using default pagination with limited results (e.g., 25 or 50 spaces) and not fetching all pages.

## Tasks
- Investigate current implementation of space list
- Check what pagination limit is being used
- Options to fix:
  **Option A**: Fetch all spaces by default (paginate through all results)
  **Option B**: Show pagination info and add flags like --limit, --all
  **Option C**: Show count and suggest how to get more
- Decide which option is best for UX
- Implement the fix
- Add indication when results are truncated

## Acceptance Criteria
- Users can see all their spaces (or know how to get them)
- Clear indication if results are limited
- No silent truncation of results
- Performance is acceptable even with many spaces

## References
- src/confl/commands/space.py — space list implementation
- src/confl/client.py — list_spaces method

## Notes
- Default behavior should be intuitive
- Consider: most users probably have < 100 spaces
- GitHub CLI 'gh repo list' shows first page + pagination info
- Could add --limit flag (default: all or reasonable limit like 100)
