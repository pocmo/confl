# Add children macro support to storage_to_markdown

Handle children macro that lists child pages.

From storage-format-feature-gaps.md: Children macro is common for navigation.

Implementation:
- Handle <ac:structured-macro ac:name="children"> elements
- Option 1 (simple): Show placeholder [Children of this page]
- Option 2 (advanced): Make API call to fetch actual children (configurable)
- Extract any parameters (depth, sort, etc.) for display

Example storage format:
<ac:structured-macro ac:name="children">
  <ac:parameter ac:name="sort">title</ac:parameter>
</ac:structured-macro>

Expected markdown:
[Children of this page]
or (if --resolve-macros flag enabled):
**Child pages:**
- Child Page 1
- Child Page 2

Priority: Medium - common for navigation, but placeholder acceptable for MVP
Complexity: Moderate - placeholder simple, API integration moderate
Decision needed: Should we make API calls or just show placeholder?
